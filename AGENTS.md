# GreenQuest 綠野尋蹤 — Agent Guide

A gamified plant identification web app (Traditional Chinese UI). Photograph plants → AI identifies → quiz for XP → level up a virtual pet.

## Repo layout

| Path | What |
|------|------|
| `backend/spacetimedb/` | SpacetimeDB module (tables, reducers, procedures, views) |
| `frontend/` | React + TypeScript + Vite + Tailwind CSS v4 |
| `cloudflare/greenquest-test/` | Cloudflare Worker AI proxy (Gemini) |
| `deploy.sh` | Full LAN deployment automation |

## Existing instruction files (read first)

- **`backend/CLAUDE.md`** — mandatory SpacetimeDB 2.0 TypeScript SDK rules (table defs, reducer patterns, index quirks, common mistakes)
- **`cloudflare/greenquest-test/AGENTS.md`** — Cloudflare Workers commands and docs links

## Two user modes

- **user** — Auth0 login, full profile/pet/shop/missions
- **guest** — no login, access-code based, limited to upload + AI

Entry: `frontend/src/pages/HomePage.tsx` switches between `UserHome` and `GuestHome`.

## Key commands

```bash
# Frontend
npm run dev          # Vite dev server (HTTPS :3001, proxies /v1 → :3000)
npm run build        # tsc -b && vite build
npm run lint         # ESLint (frontend only)

# Backend (SpacetimeDB)
spacetime start                       # local server
spacetime publish --server local <db> # publish module locally
spacetime generate --lang typescript --out-dir <dir>  # client bindings
spacetime call <db> <reducer> [args] --server local    # invoke reducer
spacetime logs <db>                   # tail server logs

# Cloudflare Worker
cd cloudflare/greenquest-test && npx wrangler deploy
cd cloudflare/greenquest-test && npx wrangler dev
```

## Required command order (deploy flow)

```
spacetime publish --delete-data --server local greenquest-db
spacetime generate --out-dir frontend/src/module_bindings --lang typescript
spacetime call greenquest-db add_ai_proxy_url <URL> --server local
spacetime call greenquest-db create_new_user root seed seed --server local
spacetime call greenquest-db activate_admin let-me-in --server local
```

See `deploy.sh` for the full automated flow (also generates self-signed SSL cert).

## NEVER edit generated code

`frontend/src/module_bindings/` is auto-generated by `spacetime generate`. Regenerate it, never edit manually.

## SpacetimeDB gotchas (from backend/CLAUDE.md)

- Indexes go in **options** (1st arg of `table()`), not columns (2nd arg)
- Reducer calls from client use **object syntax**: `conn.reducers.foo({ param: val })` not positional
- `u64`/`i64` fields use **BigInt**: `0n`, `1n` not `0`, `1`
- `.insert()` returns the **row**, not ID
- Server uses `ctx.db`, procedures use `ctx.withTx()`
- Multi-column index `.filter()` is **broken** — use single-column + manual filter
- Identity comparison: `a.toHexString() === b.toHexString()`
- Timestamps: `row.createdAt.microsSinceUnixEpoch / 1000n` for JS Date conversion
